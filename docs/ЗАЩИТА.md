# ПР2 — план выполнения и защиты по этапам

Вариант №14: NuGet, параметры из командной строки, нерекурсивный DFS,
исключение по подстроке, циклы, порядок загрузки, Graphviz/SVG и ASCII.

## Подготовка

```sh
make test
git log --oneline --decorate
git tag --list 'stage-*'
```

Приложение использует стандартную библиотеку Python 3.9+. Для SVG нужна
команда `dot` из Graphviz. Установка `dotnet` нужна только для независимого
сравнения; сам анализатор его не вызывает. Сеть требуется для NuGet,
а все файлы `examples/*.json` работают без интернета.

У каждого этапа есть отдельный коммит и тег. Для показа удобно запускать
текущую версию с `--stage N`; для просмотра истории используй
`git show stage-N:src/main.py` и `git diff stage-2 stage-3`.

## Этап 1. Настройки

```sh
./run.sh --package A --test --repository examples/diamond.json \
  --ascii --exclude SKIP --output demo.svg --stage 1
./run.sh --package '../bad' --stage 1
./run.sh --package A --output wrong.png --stage 1
./run.sh --package A --test --repository missing.json --stage 1
```

**Что показать.** Первый вызов печатает все параметры. Остальные
заканчиваются с кодом 2 и сообщением об ошибке до сетевого запроса.

**Что сказать.** «Интерфейс собран через argparse. Параметры отделены
от алгоритма: один и тот же обход можно проверить на файле или NuGet».

**Что открыть в коде.** `config.py`: `parser`, `parse_args`,
`check_repository`. Покажи проверку расширения SVG, существования
тестового файла и имени пакета. Подстрока фильтра может быть пустой:
это означает, что фильтрация отключена.

## Этап 2. Прямые зависимости

```sh
./run.sh --package Serilog.Sinks.Console \
  --package-version '[6.0.0]' --framework net8.0 --stage 2
```

Проверенный результат: зависимость `Serilog@4.0.0`.

**Что сказать.** «Сначала читаю service index NuGet, из него получаю
PackageBaseAddress. Потом читаю список версий и XML .nuspec. Готовых
менеджеров и библиотек для получения зависимостей в анализаторе нет».

**Как проходит запрос.** `NuGetRepository.resolve` выбирает точную
версию из `index.json`; `dependencies` читает `.nuspec`; `dependencies_xml`
выбирает одну совместимую группу платформы. Для `net8.0` нельзя просто
объединить все XML-группы: так в граф попадут зависимости чужих платформ.

**Почему скобки в версии.** `[6.0.0]` означает точную версию.
`6.0.0` в NuGet — минимальная разрешённая версия. Диапазон `[1.0,2.0)`
включает 1.0 и не включает 2.0. Для зависимостей выбирается минимальная
подходящая stable-версия; незакреплённый корень получает последнюю stable.

## Этап 3. Транзитивность, фильтр, циклы

```sh
./run.sh --package A --test --repository examples/diamond.json --stage 3
./run.sh --package A --test --repository examples/filter.json \
  --exclude SKIP --stage 3
./run.sh --package A --test --repository examples/cycle.json --stage 3
```

Для ромба:

```text
A -> B, C
B -> D
D -> (нет)
C -> D
```

**Что сказать.** «Использую собственный стек. Вершина попадает в
словарь посещённых до обхода детей, поэтому цикл A–B–C–A не вызывает
бесконечного чтения. Общая зависимость D загружается один раз».

**Как объяснить фильтр.** В примере `filter.json` ветка SKIP отбрасывается
целиком; остальные ветки остаются. Сравнение подстроки не зависит от
регистра. Если фильтр исключает сам корень, программа сообщает об этом.

**Что открыть.** `graph.py`, функция `build_graph`. Строка `stack.pop()`
делает обход в глубину. Смена её на очередь изменила бы порядок обхода.
Рекурсивного вызова этой функции нет; тест проходит цепочку из 1100 узлов.

## Этап 4. Порядок загрузки

```sh
./run.sh --package A --test --repository examples/diamond.json --stage 4
./run.sh --package A --test --repository examples/cycle.json --stage 4
```

**Ожидаемый результат ромба:** `D -> B -> C -> A`.
**Ожидаемый результат цикла:** понятное сообщение и код завершения 1.

**Что сказать.** «Пакет добавляется в ответ после своих зависимостей.
Состояния посещается/завершён позволяют обнаружить обратное ребро.
Топологический порядок может быть не единственным: B и C можно поменять
местами, если D всё равно предшествует обоим».

**Сравнение с NuGet.** На Serilog набор из двух пакетов совпал.
Учебный порядок — Serilog перед Serilog.Sinks.Console. В настоящем
журнале restore сначала скачан Serilog.Sinks.Console, потом Serilog.
Это не расхождение графа: порядок HTTP-скачивания отличается от порядка
«зависимость раньше потребителя». Журналы и `dotnet nuget why` сохранены
в локальном комплекте. Подробности — [СРАВНЕНИЕ.md](СРАВНЕНИЕ.md).

## Этап 5. Картинка и дерево

```sh
./run.sh --package A --test --repository examples/diamond.json \
  --ascii --output diamond.svg
./run.sh --package A --test --repository examples/cycle.json \
  --ascii --output cycle.svg
./run.sh --package Serilog.Sinks.Console --package-version '[6.0.0]' \
  --ascii --output serilog.svg
```

Открой SVG обычным браузером. Можно увеличивать изображение без потери
качества. Покажи рядом `.dot`: это текстовое описание того же графа.

```text
A
|-- B
|   `-- D
`-- C
    `-- D [повтор]
```

**Что сказать.** «Стрелка направлена от пакета к зависимости.
Graphviz отвечает за раскладку изображения, а граф строит моя программа.
Повторная вершина в дереве — ещё не цикл; цикл означает возврат
к вершине текущего пути. Цикл можно нарисовать, но нельзя упорядочить».

| Microsoft.Extensions.Configuration.Json | 8.0.0 | net8.0 | 10 | Состав и версии совпали |

Все три SVG, DOT, ASCII, порядки загрузки, native-деревья и журналы

## Что важно понимать

**Прямая зависимость** записана в самом пакете. **Транзитивная** нужна
одной из его зависимостей. **DFS** идёт в глубину со стеком. **Цикл**
не позволяет построить топологический порядок. **TFM** обозначает
целевую платформу, от которой зависит выбор группы XML.

Инструмент решает задачу графа и не заменяет весь NuGet resolver:
он не выполняет глобальное объединение конфликтующих ограничений
версий, runtime-specific assets и полный набор TFM платформ NuGet.
Различающиеся версии одного пакета остаются разными вершинами.
Неподдерживаемый TFM отвергается, несовместимые группы не смешиваются.
Совпадение трёх примеров не является доказательством совместимости
со всеми возможными проектами .NET.
