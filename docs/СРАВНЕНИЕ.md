# Сравнение с NuGet / .NET CLI

Проверено 27.10.2026 на .NET SDK 8.0.427, целевая платформа `net8.0`.
SDK получен из официального канала Microsoft и проверен по SHA-512
из release metadata. Он использован как независимый эталон; приложение
читает NuGet через urllib и XML стандартной библиотеки Python.

## Состав пакетов

| Корень | Версия | Наш граф | project.assets.json | Только у нас | Только у NuGet |
|---|---|---:|---:|---:|---:|
| Serilog.Sinks.Console | 6.0.0 | 2 | 2 | 0 | 0 |
| Microsoft.Extensions.Configuration.Json | 8.0.0 | 10 | 10 | 0 | 0 |
| Microsoft.Extensions.Logging.Console | 8.0.0 | 14 | 14 | 0 | 0 |

Сравнивались идентификаторы вместе с точными версиями, без учёта регистра.
В референсном проекте задан один PackageReference с закреплённой версией.
Из `project.assets.json` выбирались записи `type=package`, включая корень.

## Штатная визуализация

Настоящая команда .NET SDK:

```sh
dotnet nuget why comparison/serilog/Reference.csproj Serilog \
  --framework net8.0
```

Содержательная часть полученного результата:

```text
[net8.0]
  Serilog.Sinks.Console (v6.0.0)
    Serilog (v4.0.0)
```

Для Configuration.Json цепочка к System.Text.Encodings.Web:

```text
Microsoft.Extensions.Configuration.Json (v8.0.0)
  System.Text.Json (v8.0.0)
    System.Text.Encodings.Web (v8.0.0)
```

В третьем примере `dotnet nuget why` показывает несколько путей
к Microsoft.Extensions.Primitives. Наш DOT содержит те же зависимости,
но общая вершина рисуется один раз. В ASCII она повторяется с отметкой
`[повтор]`. Поэтому внешний вид разных представлений различается.

## Порядок

Наш алгоритм выдаёт зависимости перед потребителем. Для первого примера:

```text
Serilog@4.0.0 -> Serilog.Sinks.Console@6.0.0
```

В журнале настоящего restore зафиксировано обратное скачивание:
сначала `serilog.sinks.console.6.0.0.nupkg`, затем `serilog.4.0.0.nupkg`.
NuGet сначала выясняет метаданные корня, разрешает версии, использует
кэш и организует собственную загрузку. Флаг `--disable-parallel`
не превращает этот процесс в наш постфиксный DFS. Мы сравнили наборы
пакетов и цепочки, а различие физического порядка скачивания объяснили.

## Воспроизведение

```sh
./scripts/compare.sh
```

Нужен `dotnet` SDK с командой `nuget why` и доступ к nuget.org.
Можно указать путь: `DOTNET=/путь/к/dotnet ./scripts/compare.sh`.
Скрипт сохраняет результаты в `build/comparison`; эта папка исключена
из Git. Готовые результаты текущей проверки лежат в `exports/nuget`
локального комплекта, рядом с репозиторием.
